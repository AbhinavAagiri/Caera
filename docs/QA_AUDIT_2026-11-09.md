# CAERA End-to-End QA Audit

**Date:** 9 November 2026  
**Scope:** Existing CAERA application, browser UI, local node, SQLite persistence, Gemini integration, memory, knowledge, connectors, local computer access, agent runtime, security boundaries and responsive presentation.  
**Method:** The application was run locally and exercised through Chromium and its real HTTP/SSE APIs. The configured Gemini key was used only by the local node. No provider response was mocked and no test was recorded as passing without observed evidence.

## Readiness decision

**Conditional pass — not an unconditional release sign-off.**

- No CRITICAL defect was found.
- Two code defects were fixed and verified: the non-chat model catalog leak (HIGH) and a raw abort message in Tools (MEDIUM).
- One HIGH operational block remains: auto-routing selected Gemini 3.8 Flash and that model failed or stalled across real chat and agent tests. The same workflows completed with an explicit Gemini 3.5 Flash selection.
- VoiceStudio and the Notion, Logseq and Anytype integrations could not be truthfully tested because the external services/credentials were absent.

The application is suitable for continued local development, but the default model route and the untested voice/connector surfaces should be resolved before calling this build broadly ready.

### Provider/model reliability finding

Auto model routing selected `gemini/gemini-3.8-flash` for general use. It produced a 120-second chat timeout and two agent failures:

- `d80fdf74-9792-45f3-a428-dda1c919cad5`: `AGENT_MODEL_FAILED` after 9.9 s, no steps.
- `a2fcb761-43ca-4398-a6ed-7fe51ec130ed`: `AGENT_MODEL_FAILED` after 5.2 s, no steps.

With `defaultModel = gemini/gemini-3.5-flash` temporarily selected:

- `56f79255-4545-4bcb-b95a-9a44fcfe4020` completed in 6.4 s with `READY`.
- `179131c9-60c5-4936-b019-f032ceb18eca` completed in 18.7 s and executed `computer.system_info`, reporting Windows 11 Home x64 (10.0.26300) and `win32`.

The original setting (`defaultModel = null`, Auto) was restored after the test. This is an upstream/model-selection reliability risk, not proof of an agent-runtime code failure.

## Findings by severity

### CRITICAL

None.

### HIGH

1. **FIXED — Non-chat Gemini models appeared in CAERA's model picker.**  
   TTS, image, transcription, Lyria and related models were discovered and selectable. `caera/server/src/providers/geminiProvider.ts` now filters them via `isChatCapableGeminiModel()`; `caera/server/src/ai/aiService.ts` filters persisted discovery too. Verified: 30 chat models, zero non-chat IDs, picker 30 + Auto. Typecheck and production build pass.

2. **OPEN — Auto-routed Gemini 3.8 Flash is unreliable for real work.**  
   A real chat hit the 120 s timeout, and two agent runs failed before planning. Explicit Gemini 3.5 Flash completed chat recall and agent tool work. This is a provider/model-selection risk; CAERA handles it with a clear failure state, but the default route does not provide a dependable baseline. Workaround verified: set `gemini/gemini-3.5-flash` as default or enable fallback. No architectural change was made during the audit.

### MEDIUM

1. **FIXED — Raw abort error visible in Settings → Tools.**  
   React StrictMode's initial effect cleanup aborted `/api/computer`; `ComputerAccessPanel` treated the expected `AbortError` as a permissions failure and rendered `signal is aborted without reason`. The catch now ignores abort errors. Verified: no abort text after HMR/reload.

### LOW

1. Deleting the active thread did not clear `lastConversationId`; the stale ID remained in local preferences. Cleaned manually for this audit. Clear it when the active thread is deleted.
2. Production client build is 747.27 kB (216.83 kB gzip); Vite emitted a >500 kB chunk warning. Consider route-level code splitting before distribution.
3. Agent model failures are persisted with a user-facing message but the server log did not retain the upstream provider status, making the difference between 3.8 and 3.5 hard to diagnose. Add a safe provider code/status log without credentials.
4. Two initial console 500s were not reproducible and had no matching server log; low-confidence dev-environment artifact.
